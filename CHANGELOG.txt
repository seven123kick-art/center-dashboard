経営管理システム Version6 - D2 データ基盤整合改修
作成日: 2026-08-17
基準: center-dashboard-main(20260816-235512).zip

【目的】
D1〜D2-6横断レビューで確認された基礎設計の不整合を、既存UI/STATE/Storage/Cloudへ接続せず読取専用データ基盤側で整理する。
後付け例外パッチではなく、SOURCE帳票定義・業務Contract・0/UNKNOWN原則の責務を整理した。

【変更ファイル】
1. src/core/data_catalog/accounting_reconciliation.js
2. src/core/data_catalog/catalog.js
3. src/core/data_catalog/contract.js
4. src/core/data_catalog/source_normalizer.js
5. src/core/data_catalog/canonical_builder.js
6. CHANGELOG.txt（本ファイル）

【主な変更】
1. accounting_reconciliation.js
- null/UNKNOWNを0として合算していたsum()を廃止。
- 明示0は有効値として0、金額不明を1件でも含む集計は合計値nullとする。
- reconcileBySlipだけでなくsummarizeByAccountも同じ原則へ統一。
- operational_has_unknown / accounting_has_unknownを結果へ保持。
- 金額不明を含む場合はEXACT/VARIANCEを確定せずUNRESOLVEDとする。

2. catalog.js
- DATA_CATALOGの責務を「SOURCE帳票の入口仕様」へ明確化。
- 業務Entityの一意性はDATA_CONTRACTを正本とし、Catalog側のprimary_keys/link_keys重複定義を廃止。
- source_link_fields + business_entity_key_contractへ置換。
- PL_ACTUALの旧status表記をdocument_stateへ統一。
- WORKER_SALESのsource_worker_labelを主キー扱いする旧定義を廃止。
- DELIVERY_LIST/ROUTE_PAYMENTの旧center+date+head複合主キー定義を廃止し、head_noの業務一意性はContract側へ一元化。

3. contract.js
- SOURCE_FILEへfile_hash / supersedes_source_file_idを追加。
- IMPORT_BATCHへrevision_status / supersedes_import_batch_id / revision_number / document_type / center_id / target_period / 差分件数を追加。
- 旧SOURCEを削除せず改訂系譜を表現できるContractへ拡張。
- ROUTE_PAYMENT_SOURCE_RECORDを追加。
- ACCOUNTING_FACT.value_statusをData Qualityとは別の「値の確定度軸」と明記。将来ESTIMATED等を扱える余地を確保。

4. source_normalizer.js
- normalizeRoutePaymentRows()を新規追加。
- 配達ヘッド傭車料確認Excelの原行から、空欄金額=null / 明示0=0を保持。
- 既存parseHeadPaymentSheetの `|| 0` を経由しない新データ基盤用読取経路。
- 削除フラグ行もSOURCE事実として保持し、Normalizer段階では削除しない。
- 既存parser/UI/STATEには未接続。

5. canonical_builder.js
- MASTER_RESOLVER / SUBJECT_RESOLVERが現時点で意図的に未接続であることを明記。
- 実データでResolution精度確認後に正式接続する段階移行方針を明文化。
- ロジック変更なし。

【変更していないもの】
- src/field/route_analysis.js の既存parseHeadPaymentSheet
- STATE
- IndexedDB
- localStorage
- Supabase / Cloud
- center.html / UI
- 既存取込導線
- MASTER_RESOLVER / SUBJECT_RESOLVERの自動接続

【重要な既知事項】
既存parseHeadPaymentSheetには `Number(...) || 0` が残っているため、既存STATE経路では空欄と0円を区別できない。
今回は既存機能へのパッチ修正を行わず、新SOURCE Normalizerで原Excelから正しく区別できる基礎を追加した。
既存画面をCanonicalへ切替えるまでは、この既存制約は残る。
