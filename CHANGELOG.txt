Version6 D4-11 / Parallel Verified Startup
Date: 2026-08-17

PURPOSE
- Improve normal first launch without weakening D4-6/D4-10 verification rules.
- Preserve verified revisions across browser restarts via the existing IndexedDB marker.
- Remove serial waiting between Cloud Manifest verification and IndexedDB restoration.

CHANGE
1. Cloud Manifest verification starts as soon as local Storage restoration completes.
2. IndexedDB state restoration runs while the Cloud Manifest request is in flight.
3. syncBoot() reuses the already-started Manifest request instead of issuing another request.
4. Figures remain hidden until IndexedDB restoration, Manifest verification, revision/local checks, and READY all complete.
5. If Cloud revisions changed, D4-10 differential fetch behavior remains unchanged.

SAFETY
- No cache-first numeric rendering.
- No skipping Cloud Manifest verification.
- No business calculation, Canonical, Data Catalog, or Supabase schema changes.

- src/app.js
- src/core/repository/sync_coordinator.js
- CHANGELOG.txt

VALIDATION
