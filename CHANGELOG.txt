Version6 D3-14 / D3-15
Date: 2026-08-17

PURPOSE
- Correct SKFL0001 budget semantics: future half-year not yet budgeted is not a zero budget.
- Prevent budget/actual screens from displaying NOT_PLANNED_YET months as 0.
- Reframe the import UI around Data Catalog document roles instead of file extensions.

BUSINESS RULE CORRECTION
For the supplied 2026 SKFL0001, April-September are the currently prepared budget months. October-March are not yet budgeted. The zeros printed in the future half-year of SKFL0001 must therefore not be treated as explicit zero-yen budgets.

PLAN MODEL
- PLANNED: a budget exists; amount may legitimately be 0.
- NOT_PLANNED_YET: budget has not been prepared yet; no amount is materialized.
- UNKNOWN: source cannot establish the budget state.
- The supplied first-half-only SKFL0001 is stored with coverage=FIRST_HALF_ONLY.
- October-March keys are removed from plan rows for this case; they are not stored as zero.
- monthStatus is retained in planData and source metadata.

DETECTION
- For SKFL0001, if all required major accounts on the second-half page are zero while the first half contains non-zero budget values, the second half is classified NOT_PLANNED_YET.
- Missing required accounts still stop import; they are never filled with zero.

DISPLAY / CALCULATION
- getPlanRowsForFiscalYear exposes month status to plan readers without changing the persisted row schema.
- getPlanValueK returns null for NOT_PLANNED_YET / UNKNOWN months.
- pl.js and budget_actual.js stop derived expense/profit calculations for a month that is not budgeted, preventing null inputs from collapsing to a displayed 0.

DATA CATALOG
- PLAN_BUDGET canonical fields now include plan_status.
- Completion rule now covers only months whose budget is actually planned.
- NOT_PLANNED_YET is explicitly distinct from zero.

IMPORT UI
- Primary data-management tab is renamed "データ取込".
- Secondary legacy/miscellaneous area is renamed "補助取込・設定".
- Added a Data Catalog based entry panel for the seven principal sources:
  SKFL0001 budget, SKDL0002 preliminary, SKDL0003 confirmed,
  worker sales, shipper area, delivery list, route payment.
- Existing import handlers are reused; no duplicate parser or save path was created.
- Budget status shows "上期策定済・下期未策定" for the supplied first-half-only plan.

VALIDATION
- node --check PASS for all src/**/*.js.
- No Supabase schema change.
- Existing actual/import parsers are unchanged except the SKFL0001 plan parser.
- Explicit planned amount 0 remains 0; only NOT_PLANNED_YET months have no materialized amount.
