Version6 D4-14 / Storage Write Boundary Migration
Date: 2026-08-17

PURPOSE
- Continue Repository boundary migration without changing business behavior.
- Remove remaining direct STORE.save() calls from feature modules that already have Repository.Storage available.

CHANGES
- src/modules/capacity.js
  - 9 direct STORE.save() calls -> Repository.Storage.save().
- src/modules/storage_audit.js
  - 2 direct STORE.save() calls -> Repository.Storage.save().

DESIGN
- Repository.Storage.save() is a thin delegation to the existing STORE.save(), so persistence behavior and AUTO_SYNC interception remain unchanged.
- This moves feature modules away from the legacy global storage implementation and keeps Storage access behind the Repository boundary.
- core/cloud.js and field_core.js compatibility/internal calls were intentionally NOT changed in this phase because they are part of the legacy adapter/compatibility layer.

VALIDATION
- node --check PASS for both changed JS files.
- No business calculations changed.
- No STATE schema, Canonical, Data Catalog, Supabase schema, startup/readiness, or D4 UI changes.
