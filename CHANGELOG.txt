Version6 D3-16 / D3-17
Date: 2026-08-17

PURPOSE
- Consolidate the seven principal Data Catalog sources into one operational import hub.
- Make target period, registration state, CURRENT/revision status and file selection available from one screen.
- Reuse the already-tested import/save paths instead of creating duplicate parsers.

IMPLEMENTATION
1. Unified Data Import Hub
- New src/modules/data_import_hub.js.
- One target-month selector controls the operational import context.
- Seven source cards:
  PLAN_BUDGET / SKFL0001
  PL_ACTUAL PRELIMINARY / SKDL0002
  PL_ACTUAL CONFIRMED / SKDL0003
  WORKER_SALES
  SHIPPER_AREA
  DELIVERY_LIST
  ROUTE_PAYMENT
- Each card shows source role, current registration state and revision count where applicable.
- File selection is launched from the card while the existing import handler remains the single processing/save path.

2. Period synchronization
- Hub month synchronizes SKDL0002, WORKER_SALES and SHIPPER_AREA legacy selectors.
- Fiscal year for SKFL0001 is synchronized from the selected month.
- DELIVERY_LIST continues to derive delivery dates from its source PDF; no false month is injected.

3. Source-of-truth status
- Normalized source status is read from Repository.NormalizedSource manifests/CURRENT batches.
- PL_ACTUAL distinguishes PRELIMINARY and CONFIRMED.
- If CONFIRMED is CURRENT, the preliminary card is shown as superseded rather than missing.
- Budget status uses STATE.planData fiscal-year coverage and preserves FIRST_HALF_ONLY / NOT_PLANNED_YET semantics.

4. Legacy/detail controls
- Existing tested upload controls remain below the hub for compatibility and detailed operations.
- The new hub does not duplicate parser, STATE, Storage, Cloud or Supabase write logic.
- No business logic was moved into the UI.

5. UI scope
- Added only the import-hub structural CSS needed for this function.
- Full product-wide color/sidebar/login/design-system unification is intentionally deferred to D4, after D3 data/import foundations are closed.

VALIDATION
- node --check PASS for every src/**/*.js file.
- New hub has no direct STATE/full_state/Supabase write path.
- Existing input IDs and handlers remain present.
- No Supabase schema migration.
