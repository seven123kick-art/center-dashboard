Version6 Phase UI-1（2026-08-15）
サイドバーCSS一本化 ＋ 最小限のUI基盤整理

【目的】
現在実ブラウザで表示されているサイドバーの見た目（濃紺系背景、ブルー系active表示等）を
一切変更せず、shell.css / route-analysis.css / shell-extras.css の3ファイルに
分散・重複していたサイドバー関連CSS定義を、shell.css を唯一の正本として一本化した。

【変更ファイル（4件のみ）】
- assets/css/foundation/base.css
- assets/css/foundation/shell.css
- assets/css/features/route-analysis.css
- assets/css/features/shell-extras.css

【背景（実装前調査で判明した事実）】
route-analysis.css に独自の :root ブロックがあり、base.css のサイドバー用
デザイントークン（--sidebar-w / --sidebar-bg / --sidebar-hover / --sidebar-active）を
CSS読込順（base→shell→components→shell-extras→theme→capacity-loading→
route-analysis→version2）の関係で実質的に上書きしていた。
つまり「現在実際にブラウザで表示されているサイドバーの色」は、base.css記載の値
ではなく、route-analysis.css側の値（--sidebar-bg:#0f172a 等）が最終的に有効に
なっていた。今回はこの「現在最終的に有効な値」を正確に算出し、base.css /
shell.cssへ統合した。見た目を変えるための色変更は一切行っていない。

【① 変更ファイル】
base.css / shell.css / route-analysis.css / shell-extras.css

【② 各ファイルの変更内容】

■ base.css
:root のサイドバー用トークン4つの値を、実際に最終的に有効だった値へ更新。
  --sidebar-w   : 236px → 248px
  --sidebar-bg  : #182132 → #0f172a
  --sidebar-hover : rgba(255,255,255,.065) → #17233a
  --sidebar-active : #2f5f8c → #1e3a5f
（--sidebar-bg-2 / --sidebar-text / --sidebar-text-active は元々route-analysis.css
  側で再定義されていなかったため変更なし）
新規トークンの追加は行っていない。

■ shell.css
route-analysis.css / shell-extras.css 側で個別に上書きされていた直接プロパティ値を、
「現在最終的に有効な値」としてそのままマージ統合した。
  #sidebar            : box-shadow の rgba値を route-analysis.css側の値へ統合
  .sidebar-logo         : padding を route-analysis.css側の値へ統合
  .sidebar-section        : font-size / letter-spacing / color / padding を統合
  .nav-item            : margin / border-radius を統合
  .nav-item.active        : background(linear-gradient) / box-shadow を統合
  .center-fixed-box        : padding / border-bottom を shell-extras.css側の
                    最終値へ統合
  .center-fixed-label       : shell-extras.css側の最終値（font-size/color/
                    font-weight/letter-spacing/margin-bottom/
                    padding-left）へ統合
  .center-fixed-name       : shell-extras.css側の最終値（font-size/
                    font-weight:700/line-height/padding-left）へ統合
  .sidebar-top-link        : shell-extras.css内の二重定義のうち、実際に
                    最終的に有効だった値（padding/color/font-size/
                    gap/transition/border-left）へ統合
  .sidebar-top-link:hover     : shell-extras.css側の最終値（background:#243a55）
                    へ統合

■ route-analysis.css
サイドバー関連の :root トークン4行・#sidebar/.sidebar-logo/.sidebar-section/
.nav-item/.nav-item.active/.nav-item:hover の直接プロパティ上書きを削除。
非サイドバー系トークン（--bg/--surface/--border/--border2/--navy/--blue/
--text/--text2/--text3/--radius/--shadow）、および配送分析画面固有のCSS
（.saas-*、.route-*、.card、.tbl、.btn、.kpi-card 等）は一切変更していない。

■ shell-extras.css
重複していたサイドバー関連定義（.sidebar-top-link、.sidebar-top-link:hover、
.center-fixed-box、.center-fixed-label、.center-fixed-name の2回目の定義）を
削除。HTML未参照のデッドクラス（.fixed-center-box 等）、Capacity関連CSS
（.capacity-status 等）、現場分析の画面調整CSS（#view-field-* 関連）は
一切変更していない。

【⑥ 変更前後で最終CSS値が変わった箇所】
なし（意図した値変更は全て「現在最終的に有効だった値」をそのまま維持する
ための統合であり、視覚的な計算結果は変更前後で完全一致する）。

唯一、.nav-item の border-left が「明示的な0指定」から「未指定」に
変わっているが、同セレクタには既に border:1px solid transparent という
透明な指定があるため、border-left の幅が1pxか0pxかは透明色のため視覚上
区別がつかない。実務上の見た目への影響はない。

検証方法：CSS読込順（base→shell→components→shell-extras→theme→
capacity-loading→route-analysis→version2）を再現したカスケードシミュレーター
（Python、CSS変数解決・コメント除去対応）を用い、サイドバー関連の対象17
セレクタについて、変更前後の最終計算値をプロパティ単位で比較した。
17セレクタ中16セレクタが完全一致、残り1セレクタ（.nav-item）も上記の
border-left（視覚的に無害）のみの差異であることを確認した。
