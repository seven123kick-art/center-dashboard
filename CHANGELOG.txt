Version6 D4-23 / Canonical Analysis Read Models
Date: 2026-08-17

PURPOSE
- Extend the D4-22 Canonical-first read path from route profitability to shipper and worker analysis.
- Keep analysis UI code from directly joining Canonical entities.
- Never mix Canonical and Legacy rows within the same displayed month.

CHANGES
1. Added src/core/data_catalog/canonical_analysis_read_models.js
- Builds dedicated read models for WORKER analysis and SHIPPER analysis from CANONICAL_MATERIALIZER output.
- Reuses one materialization per YYYYMM and caches the read model.
- Cache is invalidated when normalized-source-updated fires.

2. Worker analysis Canonical-first
- Uses Canonical SALES_DETAIL whose primary source is WORKER_SALES.
- Recreates unique-slip counts, work days, sales/direct-sales split and work-item counts.
- Preserves the existing worker-analysis business rule: trunk/relay fee lines are excluded from worker amount analysis.
- Trunk/relay excluded amount remains separately tracked.
- If normalized WORKER_SALES is not registered, the whole month uses the existing Legacy worker record instead of mixing sources.
- UI states which data path is in use.

3. Shipper analysis Canonical-first
- Revenue amounts come from Canonical SALES_DETAIL.
- Shipper code/name metadata is supported by the verified CURRENT SHIPPER_AREA normalized source.
- Counts are unique BUSINESS_SLIP counts.
- Full shipper code provides contract level; first 3 digits provide the existing group level.
- A slip with conflicting/missing shipper code or UNKNOWN Canonical amount is not silently treated as zero; it is excluded from confirmed totals and a warning is shown.
- If normalized SHIPPER_AREA is not registered, the whole month uses the existing Legacy shipper analysis instead of mixing sources.
- UI states which data path is in use.

4. center.html
- Loads the new Canonical analysis read-model adapter after Canonical Route Ledger.

IMPORTANT
- Legacy analysis code is retained only as a compatibility fallback for months not yet migrated to normalized CURRENT SOURCE.
- No Canonical schema, Data Catalog, Supabase schema, startup synchronization or business SOURCE values are changed.
- Canonical and Legacy values are never combined into one monthly result.

  * worker unique-slip count
  * sales/direct-sales split
  * trunk-fee exclusion for worker analysis
  * shipper group/contract aggregation from canonical sales + SHIPPER_AREA metadata
