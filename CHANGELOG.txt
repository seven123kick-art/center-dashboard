Version6 D2-6 Attribution Subject Resolution
作成日: 2026-08-17

■目的
WORKER_SALES（作業者別売上明細表）の「作業者」欄を人物専用と誤認しない基礎構造へ改訂。
2026年6月実データと業務確認により、この欄は売上・支払の帰属主体であり、人物・会社・拠点/処理単位・業務処理コード・不明を含むことが確定した。

■変更ファイル
- center.html
  - subject_resolver.js 読込を1行追加。
- src/core/data_catalog/contract.js
  - SALES_DETAILをworker_id中心からattribution subject中心へ再定義。
  - source_subject_label / source_subject_company_nameを保持。
  - ROUTE_WORKER（実運行人物）との責務分離を維持。
- src/core/data_catalog/canonical_builder.js
  - WORKER_SALES由来SALES_DETAILへ新subjectフィールドを出力。
  - 人物/会社等の自動判定は行わずnullのまま（Resolver接続前の安全状態）。
- src/core/data_catalog/master.js
  - ATTRIBUTION_SUBJECT_ALIAS / PROCESS_MASTER契約を追加。
- src/core/data_catalog/subject_resolver.js（新規）
  - PERSON / ORGANIZATION / OPERATION_UNIT / PROCESS / UNKNOWNを定義。
  - 個別表記をコードへベタ書きせず、マスタ/Aliasを引数で受ける純粋Resolver。
  - PERSONのみ既存MASTER_RESOLVERへ接続可能。

■確定業務仕様
- 個人名: PERSON → WORKER_MASTER候補。
- 会社名（例: 個人を把握せず会社へ支払を立てるケース）: ORGANIZATION → COMPANY_MASTER。
- センター等へ売上を帰属: OPERATION_UNIT → CENTER等。
- 返品/未完了処理等: PROCESS。
- 空欄/未判定: UNKNOWN。
- 「習志野リサイクル」のような一括同名コードも人物として扱わない。
- 会社/拠点/処理主体であることは情報欠落ではなく、業務上意図された正常データになり得る。

■安全性
- STATE / IndexedDB / localStorage / Supabase / Cloud書込変更なし。
- 既存parser変更なし。
- 既存業務画面からsubject_resolverは未接続。
- 2026年6月の個別表記をResolverへハードコードしていない。
- UNKNOWNを架空のWORKER_MASTERへ登録しない。
