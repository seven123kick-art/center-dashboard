Version6 D4-7 / Verified Read Model Fast Startup
Date: 2026-08-17

PURPOSE
- Keep D4-6 safety rule: management figures are never shown before startup verification.
- Reduce repeated cloud downloads when the locally stored state is already the same version that was verified on the previous successful startup.

DESIGN
- Cloud Manifest is still checked on every startup.
- After a full successful startup, a verified-manifest marker is stored in IndexedDB.
- On the next startup, the current Cloud Manifest is fingerprinted and compared with that marker.
- Fast path is allowed only when center matches, Manifest fingerprint matches, and required local data is present/current.
- If any check fails, the existing D4-6 full synchronization runs.
- Failure/timeout remains blocking; unverified figures are not displayed.

PERFORMANCE
- Matching verified state skips full_state and monthly dataset downloads.
- Normal full sync reuses the already fetched full_state for dailyRecords instead of downloading it twice.

IMPORTANT
- This is not unconditional cache-first display.
- Lightweight Cloud Manifest verification always happens before figures are shown.
- Another device changing data changes the Manifest fingerprint and forces full refresh.
- Verified marker is written only after successful READY synchronization.
