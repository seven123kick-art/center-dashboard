Version6 D4-19 / Pipeline Verification & Recovery
Date: 2026-08-17

目的
- D4-17以前の既存データが「未確認」のまま残る問題を、推測せずCloudのCURRENT実体で検証してbackfillする。
- 部分完了/失敗後に、安全に再確認・Canonical再構築できる操作を追加する。

変更
1. pipeline_recovery.js 新設
   - CURRENT Manifest + CURRENT BatchをCloudから再取得。
   - batch_id一致、record_count一致を検証。
   - source_record_idが全件存在する場合のみSOURCEをOKへbackfill。
   - NORMALIZED/CLOUDはCloud実体確認後のみOK。
2. Canonical Materializer
   - 失敗時にCANONICAL / DISPLAY_SNAPSHOTをFAILEDとして明示。RUNNINGのまま残さない。
3. データ確認UI
   - 「状態を再確認・再構築」ボタン追加。
   - 主要5資料をCloud再検証後、Canonical/Snapshotを再Materialize。
   - 未登録資料は異常扱いせず件数を通知。
   - Cloud取得/整合エラーは明示。

安全性
- 未登録資料を推測でOKにしない。
- Pipeline Statusは監査/確認層であり、SOURCE原値や業務計算は変更しない。
- Supabase schema / Data Catalog / D4-11高速起動は変更なし。
