Version6 D4-30 / Accounting CONFIG Binding Fix
Date: 2026-08-17

D4-29実機結果
- 202604で ACCOUNT_ROWS_NOT_FOUND。
- confirmed Dataset自体は取得できていた。

実コード確認で確定した原因
- app.js の CONFIG は `const CONFIG = {...}` として定義された top-level lexical binding。
- `window.CONFIG` には公開されていない。
- 現行 processDataset() は `CONFIG.INCOME_KEYS / CONFIG.EXPENSE_KEYS` を直接参照して正常動作。
- D4-25 accounting_parity.js と D4-28 accounting_legacy_migration.js は誤って
  `window.CONFIG` を参照していた。
- その結果、移行対象科目キーが0件となり ACCOUNT_ROWS_NOT_FOUND になっていた。
- 同じ誤りがParityにもあり、移行後の科目比較が0キーになる潜在不具合もあった。

修正
1. accounting_legacy_migration.js
   - window.CONFIG参照を廃止。
   - 現行processDataset()と同じglobal lexical CONFIGを使用。
   - INCOME_KEYS + EXPENSE_KEYSだけを既存Dataset.rowsからPL_ACTUALへ移行。
   - CONFIG自体が見えない場合はACCOUNT_CONFIG_UNAVAILABLEとして区別。
2. accounting_parity.js
   - window.CONFIG参照を廃止。
   - 現行processDataset()と同じCONFIG科目集合で比較。
   - 収入合計・費用合計の判定も同じCONFIGを使用。
3. data_verification.js
   - ACCOUNT_ROWS_NOT_FOUND時にDataset row数もエラー表示できるよう診断補強。

重要
- 既存Dataset構造を推測変更していない。
- processDataset()の収支計算ロジックは変更していない。
- 既存Datasetは変更・削除しない。
- ホームKPI/年度推移はまだCanonicalへ切り替えない。
- D4-29のCloud読戻し厳格検証を維持する。
