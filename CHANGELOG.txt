Version6 配送分析 Phase D-1: route-analysis.css グローバル汚染解消
（2026-08-15）

【目的】
route-analysis.cssに残っていたVersion6共通UI（:root トークン・
.card/.card-header/.card-body/.btn/select/.tbl th/.tbl td/
.kpi-card/.kpi-label/.kpi-value/body/#content）の再定義を解消し、
「base.css/theme.css/components.cssが共通UIの正本、
route-analysis.cssは配送分析固有UIのみ」という責務分離を実現した。

【変更ファイル】
- assets/css/features/route-analysis.css

============================================================
assets/css/features/route-analysis.css のみ（JS・HTML・他CSSは
一切変更していない）

--bg / --surface / --border / --border2 / --navy / --blue /
--text / --text2 / --text3 / --radius / --shadow
の11個全て。base.css側に既に正式定義があるため、route-analysis.css
側の重複定義（値が微妙に異なっていた）を削除した。

============================================================
④ 配送分析固有へ移した定義
============================================================
.saas-content-card：これまで.cardとの結合セレクタ
（.card,.saas-content-card{...}）で共通クラスに依存していたが、
削除に伴い独立した定義（border/border-radius/box-shadow/
background/overflow）を明示的に持たせた。border-radiusは
var(--radius-lg,18px)としてtheme.cssと同じ値・同じトークンを参照し、
box-shadowはvar(--shadow)を参照するため、base.cssの正しい値へ
自動的に追従する。

配送分析固有クラス（.saas-page-head/.saas-eyebrow/
.saas-page-title/.saas-page-sub/.saas-head-actions/
.saas-btn-secondary/.saas-toolbar/.saas-filter-group/
.saas-filter-search/.saas-view-switch/.saas-kpi-grid/
.saas-content-head/.saas-legend/.dot/.dot-ok/.dot-warn/
.saas-table/.profit-positive/.profit-negative/.route-status/
.route-card-*/.route-detail-*）は全て#view-route-analysis配下へ
スコープした（機能・値は一切変更していない、純粋なセレクタの
先頭に#view-route-analysisを追加しただけ）。@media(max-width:1000px)
内のセレクタにも同様にスコープを適用した。

============================================================
⑤ 変更前後で最終適用値が変わった共通UI
============================================================
Pythonによるカスケードシミュレーター（CSS読込順を正確に再現、
コメント除去・CSS変数解決対応）で、削除前後の最終計算値を
プロパティ単位で比較した。

【:root トークン】11個中9個で値が変化（現状route-analysis.css値 →
修正後base.css正式値）：
  --bg: #f6f8fb → #f5f7fa
  --surface: #ffffff → #fff（実質同一）
  --border: #e8edf3 → #e4e8ee
  --border2: #d7dee8 → #d5dbe4
  --navy: #174f86 → #315f8c
  --blue: #2563eb → #315f8c
  --text2: #5d6b82 → #647086
  --text3: #94a0b2 → #98a2b3
  --shadow: 0 1px 2px rgba(15,23,42,.04),0 8px 24px rgba(15,23,42,.05)
    → 0 8px 28px rgba(31,42,61,.055),0 1px 3px rgba(31,42,61,.035)
  （--text/--radiusは元々同値のため変化なし）

【共通クラス】9個全てで一部プロパティが変化：
  .card: border-radius 14px→18px、box-shadow上記の通り
  .card-header: padding 15px 18px→14px 18px
  .btn: border-radius 9px→11px、padding 8px 14px→6px 14px
  select: padding 8px 10px→5px 8px
    （border-radius/borderはtheme.css側が既に!importantで保護して
    いたため、実質的には元々変化していなかった＝route-analysis.css
    のborder-radius:9px指定は既に無効だったデッドコード）
  .tbl th: padding 11px 12px→10px 9px、color #68758a→#475467、
    position:stickyが正しく機能するようになった（以前も定義自体は
    生きていたが、paddingの上書きにより見た目が僅かに異なっていた）
  .tbl td: padding 11px 12px→9px
  .kpi-card: border-radius 14px→16px、padding 18px→17px 18px
  .kpi-label: color #718096→#667085、letter-spacing .04em→.02em
  .kpi-value: font-size 23px→27px、letter-spacing -.02em→-.04em

  .btn-primary: 変化なし（theme.css側が!importantで既に保護して
  おり、route-analysis.css側の定義は元々無効だったデッドコード）
  .card-body: 変化なし（元々同値）

  body: font-family "Inter,'Yu Gothic UI',..." →
    "\"Yu Gothic UI\",\"Yu Gothic\",\"Meiryo\",system-ui,sans-serif"
    background: 単色var(--bg) → linear-gradient(180deg,#f6f8fb 0%,
    #f8fafc 100%)
    【確認済み】center.htmlにInterフォントのweb font読込
    （<link>等）は存在しないため、Interは多くの環境で利用不可であり
    自動的にYu Gothic UI等へフォールバックしていたと考えられる。
    実質的な見た目の差はごく僅かと判断される。背景も近似色同士の
    グラデーションのため視覚的差異は僅少。

これらの変化は、素の.card/.card-header/.tbl/.btn/.kpi-card
クラスを実際に使用している既存完成画面（pl.js/kamoku.js/
budget_actual.js/landing_forecast.js/trend関連HTML）全てに及ぶ。
これは「壊れた」のではなく、「route-analysis.cssによって意図せず
上書きされていた値が、本来のtheme.css/base.css/components.cssの
意図した値へ復元された」ことを意味する。値の差は1〜4px程度の
微差（border-radius、padding、font-size）であり、レイアウト崩壊や
機能不全を招くものではないと判断したが、実際のピクセル差を
上記の通り全て報告する。

値が変わるため、便別採算タブの一部の色・影も微妙に変化する
