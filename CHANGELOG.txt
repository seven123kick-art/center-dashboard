1. 「計画 未登録」の修正
============================================================
原因：planForYM()の
  if (!rows || !rows.length) return null;
という判定。getPlanRowsForFiscalYear()が返すrowsは配列ではなく
プレーンオブジェクト（{"科目名":{mm:値},...}）のため、.lengthは
常にundefinedとなり、!rows.lengthは常にtrueとなって、実際に
STATE.planDataへ計画データが存在していても常にnullを返していた。

修正内容：
  if (!rows) return null;
へ変更。合わせて、
  return getPlanValueK(rows, '営業収益', mm, CONFIG.INCOME_KEYS) || null;
  return getPlanValueK(rows, '粗利益', mm, []) || null;
という末尾の`|| null`も削除した。getPlanValueK()自体が「見つからな
ければnullを返す」という契約を既に持っており（pl.js/budget_actual.js
は同じ関数をこの`|| null`無しでそのまま使っている）、この末尾の
`|| null`は「計画が正当に0円として登録されている」場合にも0を
nullへ変換してしまう別のバグだったため、月次収支・予実差異分析と
同じ挙動に揃える意味でも削除した。

これにより、着地予測はpl.js/budget_actual.jsと全く同じ
getPlanRowsForFiscalYear()/getPlanValueK()/readPlanValueByLabel()を
同じ引数パターンで呼び出すだけの実装になり、独自の事前チェックを
持たない設計に統一された。

計画値の3画面照合結果：
Node.js環境で実際のgetPlanValueK/readPlanValueByLabelロジックを
再現し、STATE.planDataに2026年6月（202606）の営業収益65,000千円・
粗利益15,000千円を設定した状態で、修正後のplanForYM()が正しく
これらの値を取得できることを確認した。3画面（月次収支/予実差異
分析/着地予測）とも同一のSTATE.planDataを参照し、同一の
getPlanValueK/readPlanValueByLabelを使うため、直接ラベル
（「営業収益」「粗利益」）が計画データに登録されているケースでは
3画面の値が一致する。

【正直な報告】pl.js/budget_actual.jsは「粗利益」の直接ラベルが
見つからない場合に「収益－各費用科目」から合算するフォールバック
計算を持つが、着地予測のplanForYM()にはこのフォールバックが
元々なく、今回も追加していない（独自ロジックの新規追加になる
ため、ご指示の「不要な独自判定はできるだけ持たせない」という
方針に従い見送った）。直接「粗利益」ラベルの計画データが登録
されていれば3画面完全一致するが、フォールバック計算が必要な
特殊なケースでは着地予測だけ計画値が取得できない可能性が残る。
必要であれば別途対応をご検討いただきたい。

2. 達成率表示の修正
============================================================
共通ratio()（src/core/format.js）は変更していない。
landing_forecast.js内に新規関数achievementLabel(planK, fK)を追加し、
kpi()関数内で使用する形にとどめた（他画面・共通関数への影響なし）。

表示ルール（全て実装・検証済み）：
  計画 > 0        → 従来通り達成率%（fK/planK*100をpctLocal表示）
  計画 = 0        → —
  計画 < 0、着地 > 0            → 黒字転換
  計画 < 0、着地 = 0            → 黒字化
  計画 < 0、着地 < 0、着地が計画より改善 → 赤字縮小
  計画 < 0、着地 < 0、着地が計画より悪化 → 赤字拡大
  計画 < 0、着地 = 計画          → 計画並み

Node.js環境で7パターン全てを検証し、期待通りの文言が返ることを
確認した。また、通常の黒字計画時（計画1000/着地1200→120.0%）が
従来の計算値と完全一致することも確認した。
