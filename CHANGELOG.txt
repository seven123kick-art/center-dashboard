Version6 D4-1 / D4-2 — Design System foundation and shell unification
Date: 2026-08-17

PURPOSE
- Start D4 by fixing the root cause of the visual mismatch between the center-selection screen and the logged-in application shell.
- Rebuild shared design tokens and shell styles instead of layering another visual patch on top.
- Preserve all business/data logic.

AUDIT FINDINGS
- index.html used landing.css with an independent green/orange palette and independent radii/shadows.
- center.html used foundation/base.css + shell.css + theme.css with a separate navy palette.
- shell colors were also duplicated as hard-coded values in features/version2.css.
- center.html still contained many inline styles; D4-1 removes only shell-level inline styling. Feature-specific inline styles remain for later screen-by-screen cleanup.
- app.css already had a sensible foundation/features loading architecture, so D4 keeps that architecture and rewrites the shared foundation instead of adding a new override stylesheet.

CHANGES
1. foundation/base.css
- Rebuilt as the single shared Version6 token source.
- Added shared brand/surface/border/text/radius/shadow tokens.
- Center-specific accent remains supported: North Saitama uses blue, Toda uses orange.
- The center accent is no longer allowed to redefine the entire product visual language.

2. foundation/shell.css
- Rebuilt sidebar/topbar/content shell from shared tokens.
- Reduced unrelated purple/navy remnants.
- Unified spacing, radii, typography and active/hover behavior.
- Added reusable shell classes for brand, cloud status, session message and topbar hint.

3. foundation/theme.css
- Rebuilt shared cards/KPI/buttons/forms/tables/messages/upload areas around the same token set.
- Removed the previous purple-tinted control styling that conflicted with the shell.

4. landing.css
- Rebuilt center selection on the SAME foundation tokens as center.html.
- Center cards still retain their center identity through accent color and character art, but typography, surfaces, borders, controls and spacing now match the application.
- North Saitama changes from the isolated green landing palette to the same blue product accent used after entry.
- Toda retains orange as its center accent, matching html[data-center="toda"] in the application.

5. center.html
- Removed shell-level inline style definitions for logo mark, cloud status, session message and topbar layout.
- These are now owned by foundation/shell.css.
- Business views and behavior are unchanged.

6. features/version2.css
- Navigation group/subitem colors now reference shared shell tokens rather than a second hard-coded sidebar palette.

NOT CHANGED
- No JS business logic.
- No Data Catalog / Canonical / Repository / Supabase changes.
- No feature screen redesign yet.
- No center character images changed.
- Existing feature-specific inline styles are intentionally left for the next D4 passes rather than hidden by a global override patch.

VALIDATION
- All src/**/*.js node --check PASS.
- center.html/index.html parsed successfully.
- CSS brace balance PASS.
- Existing center query behavior preserved (kitasaitama/toda).
