Version6 D4-17 / Data Pipeline Status Foundation
Date: 2026-08-17

目的
- SOURCE → NORMALIZED → CANONICAL → DISPLAY_SNAPSHOT → CLOUD の各段階を、
  「成功 / 部分成功 / 失敗 / 実行中 / 未確認」として共通形式で追跡する基礎を追加。
- 推測で成功扱いせず、コード上で観測できた段階だけ記録する。

変更
1. DATA_PIPELINE_STATUS を新設
   - period + document_type 単位
   - SOURCE / NORMALIZED / CANONICAL / DISPLAY_SNAPSHOT / CLOUD
   - UNKNOWN / RUNNING / OK / PARTIAL / FAILED
   - IndexedDB cacheへ永続化
2. NormalizedSourceRepository
   - saveBatch結果を共通Pipeline Statusへ反映
   - batch保存済み・manifest失敗は PARTIAL + CLOUD FAILED として区別
3. Canonical Materializer
   - 再構築開始をRUNNING、正常完了をCANONICAL OKとして記録
   - 正常生成した表示SnapshotをDISPLAY_SNAPSHOT OKとして記録
4. SKDL0002取込
   - ユーザーが選択したSOURCEファイルを観測できた時点のみSOURCE OKを記録

重要
- 既存業務データ・計算結果・Canonical schemaは変更しない。
- SOURCE管理がまだ統一されていない既存取込について、推測でSOURCE OKにはしない。
- まず共通状態管理層を追加し、今後各取込経路を順次接続する。
