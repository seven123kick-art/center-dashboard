Version6 D3-6B - Existing import -> NORMALIZED SOURCE integration
Date: 2026-08-17

Purpose
- Connect the existing import entry points to the D3-6A NormalizedSourceRepository without replacing or bypassing legacy behavior.
- Preserve SOURCE -> NORMALIZED facts so Canonical can later be rematerialized after Resolution changes.

Changed files
1. src/field/field_core.js
   - WORKER_SALES import: normalize the validated original CSV rows and save a new immutable NORMALIZED SOURCE batch for the selected YYYYMM.
   - SHIPPER_AREA import: same pattern.
   - Legacy STATE update, Repository.Storage.save(), existing Cloud synchronization, UI refresh and existing parsers remain in place.
   - NORMALIZED save failure does not roll back a successful legacy import; the user is warned separately.
   - Each re-import creates a new batch; D3-6A manifest logic marks the previous CURRENT batch SUPERSEDED.

2. src/field/route_analysis.js
   - ROUTE_PAYMENT Excel import now also passes the original worksheet rows to SOURCE_NORMALIZER.normalizeRoutePaymentRows().
   - Uses file name + sheet name in source_record_id material to avoid row-ID collision across sheets.
   - Groups normalized records by delivery month and saves one immutable batch per YYYYMM.
   - Existing parseHeadPaymentSheet and existing STATE.routeData behavior are unchanged. Therefore legacy yoshaFee still follows the old parser, while NORMALIZED SOURCE preserves blank amount as null and explicit zero as 0.

Safety / behavior
- No change to existing business calculation rules.
- No change to STATE schema, full_state, IndexedDB schema, Supabase table schema, existing Cloud sync API, or UI navigation.
- New NORMALIZED persistence is additive and uses Repository.NormalizedSource only.
- Existing import success is not falsely rolled back if the new parallel persistence fails.
- SOURCE_NORMALIZER missing is treated as an import error before legacy mutation, preventing a half-normalized new import path.

Verification

- No code converts null/blank NORMALIZED amounts to zero.

Not included yet
- Automatic Canonical rematerialization from persisted NORMALIZED SOURCE.
- Automatic reload of persisted NORMALIZED SOURCE during application boot.
- PL_ACTUAL and DELIVERY_LIST normalized persistence (their SOURCE paths require separate contracts/normalizers).
