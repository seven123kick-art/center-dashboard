Version6 D3-10 / D3-11

PURPOSE
- Add a dedicated SKDL0002 PRELIMINARY import path without misusing legacy SKDL0001 daily data.
- Make NORMALIZED SOURCE current/revision status visible from the import screen.
- Prevent accounting state from moving backward from CONFIRMED to PRELIMINARY.
- Correct legacy UI wording that called SKDL0001 daily data "速報".

CHANGES
1. Dedicated SKDL0002 import
- Separate month + CSV input for SKDL0002.
- Saves through ACCOUNTING_IMPORT_BRIDGE as PL_ACTUAL / PRELIMINARY.
- Does not write SKDL0002 into legacy STATE.datasets as daily.

2. Confirmed accounting downgrade protection
- CURRENT CONFIRMED rejects later PRELIMINARY with CONFIRMED_CANNOT_DOWNGRADE_TO_PRELIMINARY.
- Existing CONFIRMED immutability remains in force.
- PRELIMINARY can still be revised until CONFIRMED is registered.

3. Import status / revision visibility
- Read-only status panel for PL_ACTUAL, WORKER_SALES, SHIPPER_AREA, DELIVERY_LIST, ROUTE_PAYMENT.
- Shows CURRENT batch, accounting state, row count and retained revision history.

4. SKDL0001 wording correction
- Existing SKDL0001 behavior is unchanged.
- UI now calls SKDL0001 日報, not 速報.
- SKDL0002=PRELIMINARY, SKDL0003=CONFIRMED remain the new Data Catalog definitions.

VALIDATION

- No direct STATE/full_state mutation added for SKDL0002.
